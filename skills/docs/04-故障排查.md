# 04 · 故障排查

全部条目都来自本工作流在真实报告上的实测记录（含失败尝试），不是二手经验。

## A. 环境类

### A1 `py` / `python` 返回 `9009`（命令未找到）

**现象**：在含中文的路径下调用 `py -m pip ...` 或 `python xxx.py`，直接返回 `9009`，无任何输出。
**原因**：Windows 的 `py` 启动器对中文路径/参数的处理问题。
**解决**：改用解释器全路径：

```powershell
& "C:\Users\<你>\AppData\Local\Programs\Python\Python311\python.exe" script.py --args
```

（本工作流自身完全支持中文路径——中文实验目录名、中文 CSV 文件名都试过。）

### A2 终端中文乱码

**现象**：脚本输出的中文在 PowerShell 里显示成 `����`。
**解决**：

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$env:PYTHONIOENCODING = "utf-8"
```

三个 checkers 的源码本身用了 `errors="replace"`，所以在任何编码下都能跑完，只是显示会花。

### A3 `check_pdf_geometry.py` 报"未安装 PyMuPDF，跳过"

**解决**：`python -m pip install PyMuPDF`。缺它时 runner 会跳过版式校验但不阻断——
**不要**在这种状态下交付（版式校验是四条判据里唯一看成品 PDF 的）。

### A4 扫描件讲义读不出文字

**解决**：`python -m pip install rapidocr-onnxruntime`，然后重跑 `--stage ocr` 或 `--stage all`。
runner 判断依据是"文本层字符数 <50 的页"，只对这些页做 OCR，正常讲义不受影响。

### A5 `kpsewhich gbt7714-numerical.bst` 为空

**解决**：TeX Live 装 `texlive-lang-chinese`；MiKTeX 用包管理器装 `gbt7714`。

## B. 流水线行为类

### B1 改了 `.tex`，PDF 却没变（最常踩）

**原因**：runner 有**讲义哈希守卫**：讲义没变、且日志里记录的正文哈希未变时，会跳过正文生成与编译。
**解决**：加 `--force`：

```powershell
python ...\run_lab_workflow.py --workspace . --stage all --force
```

（本次打包过程中我自己就被它骗过一次：`--stage all` 跑完"成功"，但 PDF 的时间戳比 `.tex` 还早，
里面还是旧内容。**判断是否真的重建了，看 PDF 与 .tex 的修改时间，或直接在 PDF 里搜一句新写的话。**）

### B2 `[compile-guard] ❌ 正文已过期`

**原因**：`generation_log.md` 里记录的 `lab_report.tex SHA-256` 与当前文件不一致。
除了"确实改过正文"，还有一种情况：**用会改编码/换行的工具手改了 `generation_log.md`**
（例如 PowerShell `Set-Content`），导致守卫读不到那一行。
**解决**：`--force` 重跑一次，让 runner 重新记录哈希；以后不要手改日志文件
（要改就用 Python 以 `encoding="utf-8", newline=""` 写回）。

### B3 `--workspace` 给错层级，报告目录里被建出 `lab_report/lab_report/`

**现象**：本想指向实验目录，却指到了 `<实验>/lab_report`，于是在报告目录下又建了一套脚手架。
**规则**：`--workspace` 应指向**实验目录**（里面直接包含 `<实验>.pdf`、`data/`、`lab_report/`）；
若指向工作区根目录，则需配合 `--experiment <实验标题>`。
**清理**：删掉误建的子目录即可（脚手架只在其中创建文件，不覆盖你的产物）。

### B4 `tables[note] 自然宽度超版心，已改用 p 列`

**含义**：该表按 `\scriptsize` 估算放不进半栏，脚本自动改用 `p{...}` 列（仍能放进版心，
但每列宽度平分）。这是正常提示，不是错误。若某列明显需要更宽，就该拆表。

### B5 表题太短/表头不对

**解决**：写 `lab_report/table_captions.json`（CSV 文件名 → 表题）与 `table_headers.json`
（CSV 文件名 → 表头数组）。改了之后重跑 `--stage tables`。

## C. LaTeX / 版式类

### C1 `Argument of \@newcommand has an extra }`

**原因**：在 `\twocolumn[...]` 的**可选参数内部**写了带可选参数的宏定义
（如 `\newcommand{\databox}[1]{...}`）——`[1]` 里的 `]` 会提前结束 `\twocolumn` 的可选参数。
**解决**：不要在里面定义宏；数据说明框直接写

```latex
\noindent\fcolorbox{black!35}{gray!8}{%
\parbox{\textwidth}{\textbf{数据说明：}...}}
\vspace{4.2em}
```

（`\vspace{4.2em}` 用来抵消 `empAbstract` 自带的 `\vspace{-3em}`，避免灰框下边框穿过摘要首行。）

### C2 `pdf-geo` 报"两行文字重叠"：首页正文压住页脚

**解决**：正文第一节开头加 `\enlargethispage{-3.3cm}`。若报的是**图形横线穿过文字**，
那是图内元素遮挡（如 matplotlib 图例压线条），改图而不是改版面。

### C3 表格被排到纸外（编译不报错！）

**现象**：PDF 里表格右半边消失，或横线伸到纸外；日志只有一条 Overfull hbox。
**解决**：用 `make_data_tables.py` 重新生成（列宽自适应）；列数 >7 就拆表；
`check_report_tex.py` 会在编译前就估算出"自然宽度超版心"。

### C4 图内文字看不清

**原因**：图按大尺寸出图后被 `\includegraphics[width=...]` 缩小，字号一起缩小。
**解决**：按最终尺寸出图——半栏 `figsize` 宽 3.15 in、字号 ≥8 pt、`width=\columnwidth`；
通栏用 6.5 in + `figure*`。`check_pdf_geometry.py` 会检测 <8 pt 的小字成簇。

### C5 页面出现大片空白 / 浮动体跑到很远

**原因**：浮动体排队（LaTeX 把 `table*`/`figure*` 排在页顶，一多就排队）或按 `t/b/p` 漂移。
**解决**（本工作流已固化的做法）：双栏 + `table[H]`/`figure[H]` **就地**放置 + 声明紧跟引用句；
`check_float_distance.py` 量"隔几页"，`check_inline_distance.py` 量"隔多少 pt"。

**不要**用全局 `\FloatBarrier`/`flafter`/`dblfloatfix` 硬压：实测页数 13 → 16、出现 4 处大空白
（最大 438 pt）。详见 `docs/03-校验与验收.md` §4.5 反面清单。

### C6 公式里出现字面 `$B_{res}$` 或表头被拆行

**原因**：早期版本的表格生成脚本把 `$...$` 里的内容也转义了。
**解决**：现行版本（v1.24+）保留 `$...$` 内内容不转义——表头里可以正常写 `$T^2/\mathrm{s^2}$`。
若看到字面美元符号，说明该表片段是旧脚本生成的，重跑 `--stage tables` 即可。

### C7 `check_inline_distance.py` 报"题注在另一栏"

**含义**：引用句正好在栏底，浮动体落到了**相邻栏的栏顶**。阅读顺序上它仍紧跟该句，
但视觉上要跨栏找。**解决办法**：把引用句所在段落写短一点，或把该句挪到一段的开头，
让"引用句 + 浮动体"能在同一栏内放下（demo 里就是这么处理的）。

## D. 工程卫生（本次打包过程中总结）

| 教训 | 做法 |
| --- | --- |
| 正则改 `.tex` 极危险 | 用 `\begin{figure}...\end{figure}` 这类正则在整篇上替换，会从**第一个**浮动体开始匹配，一次删掉半个文档（实测 16 页 → 8 页）。改结构一律①先备份到 `%TEMP%`，②按**行号 + 断言**做精确修补，③写盘前跑自检（章节/标签数/关键字符串计数）。 |
| 别用内联 PowerShell 写 Python | 单引号字符串里的 `\n` 会变成字面 `\n`，写出语法错误的脚本。用写文件的方式生成补丁脚本，再 `py_compile` 验证。 |
| 改数据先看权威源 | `lab_report/data/` 是镜像，改了会被覆盖；要改 `<实验>/data/`。 |
| 判据本身要先用真实 PDF 验证 | 本工作流有两条"假告警"（图的题注在图下方被算成间距、分式的分子分母被当成两行重叠），差点为假的 177 pt 去改本来是 22 pt 的版式。 |
