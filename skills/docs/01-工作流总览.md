# 01 · 工作流总览

## 一句话

**讲义 + 数据 → 目录结构 → 图表与表格 → 正文（由 AI 按规则写）→ 编译 → 量成品 PDF 版式**。
每一步的产物都落在固定位置，任何一步都能单独重跑。

模板选择仅针对本份/本次报告；其他实验曾选过的样式不得自动套用。用户明确要求沿用上一份样式时可沿用；新实验没有本次选择则重新列六种供用户选择。

制作新实验报告前，先检查已有报告和 `template_selection.json`：已有报告或选择记录继续沿用，换版须有用户明确要求并保留正文、数据和手动修改。用户本轮或此前已明确选定模板时沿用，不重复询问；否则先列出以下六种模板，请用户明确选择后再部署和撰写，不擅自默认任一模板。

| 编号 | 模板 | 版式特点 |
| --- | --- | --- |
| 01 | 清华课程双栏 | 居中题头、传统双栏 |
| 02 | Physical Review 风格 | 紧凑双栏、栏间细线 |
| 03 | Nature 风格 | 大标题、浅色摘要；引言单栏，原理起同页双栏，附录单栏 |
| 04 | Applied Physics Letters 风格 | 浅色题头、无首行缩进、段落留白、单栏宽图表 |
| 05 | Journal of Physics 风格 | 题头与摘要独立页、大字号与行距、单栏宽图表 |
| 06 | He-Ne 原报告单栏 | 黑白、1.5倍行距、题目页眉与就地图表；宋黑字体由 Fandol 替代 |

选定后直接填写 `lab_report/lab_report.tex`，不拆 metadata/body。六种模板保留各自版式，共用 XeLaTeX、Fandol/Latin Modern 和自动章节编号。实验内容按 `report.md` 填写；`minimal_latex` 仅用于独立故障诊断。

```powershell
python Lab_Workflow_Generator/scripts/select_report_template.py --list-templates
# 仅在用户已经选择01时部署；01不是默认项：
python Lab_Workflow_Generator/scripts/run_lab_workflow.py --workspace . --experiment "实验标题" --stage scaffold --template 01
```

## 全流程

```text
               ┌─────────────────────────────────────────────┐
 讲义 PDF ────▶│ ① 脚手架 scaffold                            │
（扫描件也行） │   建 preview_report/ lab_report/{data,figures,│
               │   scripts,tables,build} 并复制模板与规范      │
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
 <实验>/data/ ─▶│ ② 数据镜像 data                              │
 （权威源）    │   <实验>/data/* → lab_report/data/*（只增不删）│
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
               │ ③ 讲义 OCR（仅扫描件，文本层 <50 字符的页）    │
               │   → lab_report/lecture_ocr.txt               │
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
               │ ④ 数据脚本 plots                             │
               │   scripts/generate_plots.py → figures/*.pdf  │
               │                              → data/*.csv（派生）│
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
               │ ⑤ 数据表格 tables                            │
               │   data/*.csv → tables/*.tex（按所选栏宽三线表）  │
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
 正文 .tex ◀───│ ⑥ 正文撰写（AI，按文本核心规则）              │
               └─────────────────────────────────────────────┘
               ┌─────────────────────────────────────────────┐
               │ ⑦ 源码检查 check：题注/引用/章节/表宽/字数     │
               │ ⑧ 编译 compile：xelatex(×2) 或 +bibtex        │
               │ ⑨ 版式校验：越纸·重叠·穿字·小字·浮动体·紧贴度  │
               └─────────────────────────────────────────────┘
                                │
                                ▼
        lab_report.pdf ＋ generation_log.md ＋ 四项校验结果
```

一键执行（在实验目录内）：

```powershell
python "$HOME\.codex\skills\Lab_Workflow_Generator\scripts\run_lab_workflow.py" `
       --workspace . --stage all --template 01 --force
```

示例中的 `--template 01` 必须替换为本份报告已明确选定的编号；01不是默认项，这条重跑命令不授权换版。

## 阶段与产物对照

| 阶段（`--stage`） | 做什么 | 产物 | 失败时 |
| --- | --- | --- | --- |
| `scaffold` | 建目录、部署用户所选01—06模板的自包含 `lab_report.tex`、校徽和规范/数据说明 | 目录骨架、`.gitkeep` | 报错并列出缺项 |
| `status` | 打印工作区自检：讲义、data、figures、脚本、正文是否就位 | 终端清单 | — |
| `ocr` | 逐页判断文本层，必要时渲染 OCR | `lecture_ocr.txt` | 缺 `rapidocr` 时跳过并提示 |
| `plots` | 执行 `scripts/generate_plots.py` | `figures/*.pdf`、派生 CSV | 输出 traceback，标注待修 |
| `tables` | `data/*.csv` → `tables/*.tex` | 三线表片段、`all_tables.tex` | 超宽表报 `FAIL` 并提示拆表 |
| `check` | 源码规则检查 | 终端报告 | 有 error 时非零退出（`--strict` 含 warning） |
| `compile` | XeLaTeX 两遍，缓存集中到 `build/`；真实 `.bib` 库按需加文献流程 | `lab_report.pdf` | 保留 `.tex` 并给日志摘要 |
| （compile 后自动） | 成品 PDF 版式、浮动体距离、紧贴度 | 三项终端报告 | 只告警不阻断 |
| `all` | 以上全部 | — | — |

## 谁做什么（确定性 vs AI）

| 工作 | 由谁做 | 为什么 |
| --- | --- | --- |
| 建目录、镜像数据、跑脚本、生成表格、编译、量 PDF | **脚本** | 可重复、可审计、不引入随机性 |
| 章节结构、论证、误差讨论、措辞 | **AI（文本核心规则）** | 需要理解物理与讲义内容 |
| 数据 | **你** | 脚本不编造数据；缺测就写"缺测/待补充" |
| 最终复核 | **你** | 封面信息、实测声明、参考文献、教师签名位 |

数据表格阶段生成本地表片段，正文只选用必要数据；实验数据附录的移除、原始材料保留与引用检查，按工作区 `report.md` 的“原始数据保存与附录范围”执行。

## `generation_log.md`

每次运行都会更新，记录：讲义 SHA-256 与状态（UNCHANGED/CHANGED）、正文 SHA-256、
本轮是否重新生成正文、数据处理脚本是否执行、两次编译结果、异常与警告。
它是"这份报告是怎么来的"的凭据，也是 `--force` 守卫判断"正文是否过期"的依据。

> 该文件的哈希行由脚本写入，**不要用会改动编码/换行的工具手改**（例如 PowerShell 的
> `Set-Content`），否则守卫会读不到记录的哈希并报"正文已过期"。

## 与 `/build_lab` 的关系

- `/build_lab`（在支持 Skill 的会话里说这句话）= 让 AI 读取工作区、按文本核心规则写正文，
  然后调用本流水线的确定性步骤；
- 本流水线的脚本**不会**替你写正文——`run_lab_workflow.py` 只做确定性步骤，
  这样"哪部分是机器算的、哪部分是人写的"始终清楚。
